Read `docs/design/direction.md` and the relevant approved decision in `docs/STATUS.md` from the project root. Before application development, check Ishe's design approval; the user explicitly requested this gate. Research and disposable review artifacts may proceed.

Design for industrial buyers: credible equipment, easy brand choice, distinct expertise. Use the warm industrial / cool precision relationship and shared type rhythm. Challenge generic layout reflexes with subject placement, negative space and mixed type scales, not arbitrary effects. No diagonal seam, glow, equal card grid or fake telemetry. Ishe's supplied media takes precedence over illustrative substitutes.

For new compositions, show desktop and mobile together. For revisions, preserve approved elements unless the request changes them. Small labels must remain readable; visual hierarchy cannot rely on colour or hover alone. Keep source-image constraints visible in design notes without putting implementation commentary inside the visitor experience.

Translate approved decisions into reusable tokens and focused components. Interactive leaves own client logic; static content stays server-renderable. Use `next/font` or local font files in production, retaining licenses. Do not install a design system because it appears in an upstream example.

Deliver a concrete draft before asking for design approval. Record that decision once; do not repeatedly ask for already-approved work.
